# 2026-05-15

## GC correction bug fix at predict time

External agent flagged a discrepancy between CV and external test. Root cause: `CFDNAModel.predict` was applying the *training-set mean LOWESS curve* to test samples instead of fitting a per-sample LOWESS on the test set.

GC correction is per-sample by construction (LOWESS of coverage vs GC fit on each row independently). CV in `cv_svm` already did this correctly: train and test folds were each GC-corrected independently after standardisation with the training-fold mean/std. `train_model` also corrected per-sample. Only `predict` was wrong.

The stored `gc_state['mean_fitted']` (average of training-sample LOWESS curves) was a single curve subtracted from every test row, which:
1. does not remove the test sample's own GC bias (each sample has its own LOWESS shape),
2. is inconsistent with the per-sample residuals the SVM was trained on, and
3. is inconsistent with CV — held-out CV AUC would not predict external test AUC.

### Changes

- `scripts/generalized_modelling/modules/gen_cfdna_model.py`
  - Removed `_fit_gc_correction` and `_apply_gc_state`.
  - `train_model` now uses `_gc_correct` directly (per-sample LOWESS), no `gc_state` saved in the pickle.
  - `predict` now runs per-sample LOWESS on the test matrix via `_gc_correct` after applying the training scaler. Raises if `gc_content` was not provided to the test-time `CFDNAModel`.
- `scripts/generalized_modelling/gen_svm_test.py`
  - Optional 4th arg `gc_path`. Loads the GC content CSV when the pickle has `gc_correction=True`, passes it into `CFDNAModel(gc_content=...)`.
- `scripts/generalized_modelling/gen_svm_test.sbatch`
  - Now passes `data/processing/gc_content_per_region.csv` as the 4th arg to the test script.

### Old pickle compatibility

Old pickles trained before this patch still have `gc_state` keys. Predict ignores them. Training-time GC correction was already per-sample, so old training matrices were correct. **No retraining required** — only retest with the patched code.
