## Note: MAPQ filtering in finaledb workflow vs feature computation

The finaledb snakemake workflow does **not** apply any MAPQ filter during fragment extraction. The `samtools view` command uses `-f 3 -F 3852 -G 48 --incl-flags 48` (proper pairs, no duplicates, no secondary/supplementary) but **no `-q` flag**. All fragments are written to the `.frag.bed.gz` file with their mapq value stored in column 5.

MAPQ filtering is applied entirely post-hoc in `compute_features_mapq.sbatch` / `sample_prep_script.sh` when computing features. The differences seen between mapq0/15/30/45 in the RBF CV1 results are therefore real and reflect genuinely different fragment populations — there is no hidden floor at mapq 20 in the source data.
